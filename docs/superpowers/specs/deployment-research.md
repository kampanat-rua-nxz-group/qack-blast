# Deployment options and cost for Qack Blast

Checked 2026-09-28. Prices are USD and may change. This is research, not a deployed service.

## What must be hosted

The project has two distinct pieces. `README.md` documents a static Godot Web export and a headless authoritative Godot process. The browser reads `?server=wss://...`; an HTTPS game page needs a public TLS WebSocket endpoint. Room codes and scores exist only in server memory, so process sleep, restart, or replacement erases all rooms and scores and disconnects players. The current export preset has `variant/thread_support=false`, which avoids a browser cross-origin isolation requirement for threading. The local build has a 38 MiB `build/web/index.wasm` file and a roughly 104 KiB PCK file (local `du` measurement on this date).

## Static browser client

| Host | Recurring entry cost and relevant limits | Fit for current export |
| --- | --- | --- |
| [itch.io HTML5](https://itch.io/docs/creators/html5) | No separate asset host needed for an HTML5 game. Upload a ZIP with `index.html`; at most 1,000 files, 500 MB extracted total, and 200 MB per extracted file. | The 38 MiB WASM is within the per-file limit. The game runs in an iframe, so the public game-page query string may not reach the embedded game. The current `?server=` configuration needs an iframe-specific check or a code change before using itch.io. |
| [GitHub Pages](https://docs.github.com/en/pages/quickstart) | Available on a public repo with GitHub Free. A published site can be at most 1 GB, with a [soft 100 GB/month bandwidth limit](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) and possible rate limiting. | **Simplest fit for the current client:** a standalone URL can carry `?server=` directly, and the 38 MiB WASM fits the site limit. GitHub says Pages is not intended for a commercial SaaS or online business; review intended use if monetization becomes a goal. |
| [Cloudflare Pages](https://developers.cloudflare.com/pages/functions/pricing/) | Static asset requests are free and unlimited. Free plan allows [500 builds/month, 20,000 files, and at most 25 MiB per single asset](https://developers.cloudflare.com/pages/platform/limits/). | **Does not accept the current 38 MiB WASM as-is.** It becomes possible only if a valid smaller export is produced, or the large asset is served from another host such as R2 with appropriate cache and CORS setup. It is not the simplest first deployment. |
| [Render Static Site](https://render.com/docs/static-sites) | Free to deploy from a connected private Git repository, with a public `onrender.com` URL. Static traffic shares the Hobby workspace's [5 GB/month included outbound bandwidth](https://render.com/pricing) with the server. | **Chosen for this repository**, which appears private. Render documents no per-file cap in its static-site guide; validate the 38 MiB WASM on the first live deploy. |

These hosts serve only files; none runs the existing GDScript room server. itch.io automatically compresses uncompressed `.wasm` and `.pck` files on delivery, per its [HTML5 upload documentation](https://itch.io/docs/creators/html5).

## Authoritative WebSocket server

| Host | Cost and behavior | Fit and caveats |
| --- | --- | --- |
| [Render Free web service](https://render.com/docs/free) | $0 compute, one Free service can run for up to 750 instance-hours per workspace/month. It sleeps after 15 minutes with no inbound HTTP request **or incoming WebSocket message**; a new WebSocket connection wakes it, taking about one minute. Free services may restart at any time. Hobby workspace includes [5 GB/month outbound bandwidth](https://render.com/docs/outbound-bandwidth), then $0.15/GB if a payment method is linked; without one, services suspend after the allowance. | **Best no-cost proof of concept.** Render accepts public [WebSocket connections](https://render.com/docs/websocket) and terminates TLS, providing `wss://<name>.onrender.com`. Render requires an HTTP listener on `0.0.0.0:$PORT`; the Docker image runs nginx there to answer HTTP probes and proxy WebSocket upgrades to Godot on `127.0.0.1:9080`. Sleep/restart erases in-memory rooms. WebSocket messages count toward outbound bandwidth when sent to players. |
| [Render Starter web service](https://render.com/pricing) | $7/month for 512 MB, plus any bandwidth beyond the workspace's 5 GB/month at $0.15/GB. Paid compute does not sleep. | **Simple always-on upgrade** if the Godot process fits 512 MB. Still subject to deploys/restarts and loss of in-memory rooms. Verify actual headless memory use under load. |
| [Oracle Cloud Always Free VM](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) | $0 within Always Free quota: up to two AMD micro VMs (1 GB each), or Arm A1 totaling 2 OCPUs and 12 GB RAM equivalent, plus 200 GB block storage and 10 TB/month outbound transfer. | **Possible $0 always-on VM**, but operationally heavier: install Godot headless, run a service manager, expose ports, and terminate TLS for `wss://`. VM capacity may be unavailable in the account's home region, and Oracle may reclaim *idle* Always Free instances based on seven days of low CPU/network/memory use. Arm builds need an Arm-compatible Godot binary or build; AMD micro is x86 but only 1 GB RAM. Availability is not guaranteed. |
| [Railway Free](https://docs.railway.com/pricing/plans) | $0 subscription with $1/month usage credit after a [one-time $5, 30-day trial](https://docs.railway.com/pricing/free-trial). A running service is charged for RAM ($10/GB-month), CPU ($20/vCPU-month), and egress ($0.05/GB). | Good deployment experience, but **$1 does not imply an always-on free server**. For example, holding 256 MiB continuously costs about $2.50/month for RAM alone, before CPU and egress (calculation from published rates). Hobby is a $5/month minimum including $5 of usage. |
| [Fly.io Machines](https://fly.io/docs/about/pricing/) | A running shared 1x CPU/256 MB machine starts around $2/month in listed regions, with storage and egress separate. The [trial](https://fly.io/docs/about/free-trial/) is only 2 VM-hours or 7 days, whichever comes first. | Low-cost paid option with more setup. The public price varies by region and resources; 256 MB may be too small for Godot. Not an ongoing free host for a new account. |
| Self-hosted computer | No cloud compute fee if hardware and internet already exist; electricity, connection, and possibly domain/IP service still cost money. | Can run Godot persistently, but requires public reachability or a tunnel/reverse proxy, TLS, uptime, security maintenance, and a network that permits hosting. No precise zero-dollar claim without the user's network and power details. |

Cloudflare Workers/Durable Objects have a [free WebSocket-capable tier](https://developers.cloudflare.com/workers/platform/pricing/), but they cannot run this Godot headless executable unchanged. Using them would mean porting the authoritative rules and room state to JavaScript/TypeScript or another supported Workers runtime, which is a separate project.

## Suggested path

1. For an initial public test from the existing private repository, deploy the **Render Static Site and Render Free Web Service** in `render.yaml`. This has a $0 base cost under the listed allowances. The static build receives the server's public hostname from the Blueprint and embeds its `wss://` URL, so players use a short site link. Expect the first connection after idle to take roughly a minute and to create a fresh server state. The current client does not retry a failed connection automatically, so a player may need to reconnect after wake-up.
2. If idle wake-up is unacceptable, upgrade only the server to **Render Starter at $7/month**. If staying at $0 matters more than easy operations, evaluate **Oracle Always Free** after checking account/region capacity and a working TLS setup.
3. Before announcing a public URL, validate two browsers joining a room through the actual HTTPS page and WSS service, then verify reconnect behavior after a server restart. Confirm Godot's headless memory usage against the chosen plan and watch outbound snapshots against the host's bandwidth allowance.

### Concrete deployment sequence

1. The repository contains a `Dockerfile` with the [official Godot 4.7.2 Linux x86_64 binary](https://godotengine.org/download/archive/4.7.2-stable/) and `render.yaml` for a Free Web Service. Create a Render Blueprint from that file. nginx binds `0.0.0.0:$PORT`, answers HTTP probes, and proxies WebSocket connections to Godot. Confirm a WebSocket connection upgrades through its public `wss://` URL.
2. The same Blueprint creates a free Render Static Site. Its build script installs matching 4.7.2 Web export templates, gets the server's `RENDER_EXTERNAL_HOSTNAME` through a [cross-service environment reference](https://render.com/docs/blueprint-spec), embeds `wss://<host>` in the Godot project setting, and publishes `build/web`.
3. Share the static site's `https://<name>.onrender.com` URL. Once connected, the host shares the six-character room code separately. `?server=` remains available for a temporary override.

The hosting prices above exclude a custom domain. Provider subdomains are enough for the first deployment. Do not estimate player capacity from plan RAM alone; measure with the actual server and snapshot rate.
